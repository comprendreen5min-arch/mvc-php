ComponentFiles — Layout Assembly Helper

The ComponentFiles class (located at app/helpers/ComponentFiles.php) is a static helper that assembles the common layout partials (header, navbar, sidebar, breadcrumb, footer) into your views. It provides two layout modes: the full authenticated layout and a minimal public layout.

1. Layout Architecture

File Locations
All layout partials live in the app/views/inc/ directory:
app/views/inc/
├── header.php ── HTML <head>, CSS imports, meta tags
├── navbar.php ── Top navigation bar
├── aside.php ── Left sidebar menu (role-based)
├── breadcrumb.php ── Breadcrumb navigation trail
├── copyright.php ── Copyright footer text
├── footer.php ── Closing tags, JS scripts
├── _header.php ── Minimal public HTML <head>
└── _footer.php ── Minimal public closing tags
Two Layout Modes
The class provides two pairs of methods — one for the authenticated dashboard layout (with sidebar + navbar) and one for public/minimal pages (login, error pages, etc.).
LayoutHeader MethodFooter MethodUse Case
Full (Dashboard) ComponentFiles::header() ComponentFiles::footer() All authenticated pages with sidebar, navbar, breadcrumb
Minimal (Public) ComponentFiles::_header() ComponentFiles::_footer() Login, registration, password reset, error pages

2. Full Dashboard Layout

ComponentFiles::header()
Loads the four partials that form the top portion of every authenticated page. Must be called at the very beginning of every view file.
What it loads (in order)
public static function header()
{
    require_once '../app/views/inc/header.php';      // <html>, <head>, CSS
    require_once '../app/views/inc/navbar.php';      // Top navbar
    require_once '../app/views/inc/aside.php';       // Left sidebar menu
    require_once '../app/views/inc/breadcrumb.php';  // Breadcrumb trail
}
Note: The aside.php partial uses Helper::renderMenuItem() to render menu items based on the current user's role. See the Menu Rendering docs for details.
ComponentFiles::footer()
Loads the bottom partials that close the page. Must be called at the very end of every view file.
What it loads (in order)
public static function footer()
{
    require_once '../app/views/inc/copyright.php';  // Copyright bar
    require_once '../app/views/inc/footer.php';     // Closing </body>, JS scripts
}

3. Minimal Public Layout

ComponentFiles::_header()
Loads a stripped-down HTML <head> with no navbar or sidebar. Used for pages where the user is not authenticated (login, register, error pages). 
public static function _header()
{
    require_once '../app/views/inc/_header.php';  // Minimal <html>, <head>
}
ComponentFiles::_footer()
Closes the minimal layout page. No copyright section or dashboard JavaScript. 
public static function _footer()
{
    require_once '../app/views/inc/_footer.php';  // Minimal closing tags
}

4. Usage in View Files

Example 1: Authenticated Dashboard View
The standard pattern for any page inside the dashboard. Your content goes between header() and footer().
File: app/views/partnersproducts/index.php
<?php ComponentFiles::header(); ?>

<!-- ===== Your page content starts here ===== -->
<div class="page-content">
    <div class="container-fluid">
        
        <h4 class="mb-3">Partner Products</h4>

        <?php Helper::showFlash('partner_product_message'); ?>

        <div class="card">
            <div class="card-body">
                <table id="datatable" class="table">
                    <!-- table content -->
                </table>
            </div>
        </div>

    </div>
</div>
<!-- ===== Your page content ends here ===== -->

<?php ComponentFiles::footer(); ?>
Result: The page will render with the full top navbar, left sidebar with role-based menu items, breadcrumb trail, your content area, and the copyright + JS footer.
Example 2: Public / Login Page View
Login and registration pages use the minimal layout — no sidebar, no navbar, just the bare HTML shell.
File: app/views/logins/index.php
<?php ComponentFiles::_header(); ?>

<!-- ===== Login form content ===== -->
<div class="account-pages my-5 pt-5">
    <div class="container">
        <div class="row justify-content-center">
            <div class="col-md-8 col-lg-6">
                <div class="card">
                    <div class="card-body p-4">
                        <h4 class="text-center mb-4">Sign In</h4>
                        <form action="<?= URLROOT ?>/logins/login" method="POST">
                            <!-- login fields -->
                        </form>
                    </div>
                </div>
            </div>
        </div>
    </div>
</div>

<?php ComponentFiles::_footer(); ?>

5. Which Layout to Use?

Use this quick decision guide:
ScenarioHeaderFooter
Dashboard pages (bookings, products, settings, users…) ComponentFiles::header() ComponentFiles::footer()
Login / Registration / Password reset ComponentFiles::_header() ComponentFiles::_footer()
Error pages (404, 403, 500) ComponentFiles::_header() ComponentFiles::_footer()
Print-friendly / PDF export views ComponentFiles::_header() ComponentFiles::_footer()
AJAX partial responses (JSON / HTML fragments) Neither — return raw output
Never mix layouts. Using ComponentFiles::header() with ComponentFiles::_footer() (or vice-versa) will result in broken HTML with unclosed tags or missing JavaScript.
