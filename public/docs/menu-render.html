Menu Rendering & Sidebar Navigation

Complete guide to the role-based sidebar navigation system. The menu is rendered inside app/views/inc/aside.php using the static method Helper::renderMenuItem() defined in app/libraries/Helper.php.

1. How the Menu System Works

The sidebar lives in app/views/inc/aside.php and is automatically loaded by ComponentFiles::header() on every page. Each menu item is rendered using Helper::renderMenuItem(), which checks the current user's $_SESSION['user_role'] against an array of allowed role IDs. If the user's role is not in the list, the menu item is silently hidden — no errors, no redirects, just an empty string.
Key Concept: The sidebar only controls visibility. It hides links from users who shouldn't see them, but it does not enforce access control. You must also use SessionHelper::requireRoles() in your controller constructor to block unauthorized access at the backend level.

2. Role ID Reference

Every user in the system has a user_role stored in the session. The following IDs are used throughout the menu and access control layers:
Role IDNameDescription
1AdminFull system access. Can manage all users, products, settings.
2ManagerOperational access similar to Admin with restricted settings.
3PartnerAgency owners — manage bookings, customers, invoices.
4TransporterTransportation providers — manage vehicles, drivers, bookings.
5DriverIndividual drivers assigned to transporters.
6PilotBalloon pilots managing flight operations.
7AccounterFinancial staff handling accounting and invoices.
8GreeterFront-line staff greeting and checking in guests.

3. renderMenuItem() Method

Helper::renderMenuItem($title, $icon, $url, $subItems, $allowedRoles)
Generates a sidebar <li> menu item with optional sub-menu dropdown. The item is only rendered if the current user's role is included in $allowedRoles. If $allowedRoles is empty, the item is visible to everyone.
Parameters
ParameterTypeDefaultDescription
$title string — The visible label of the menu item (e.g. 'Products').
$icon string — CSS icon class from Font Awesome or Themify. Example: 'fas fa-box', 'ti-home'.
$url string 'javascript:void(0);' The link target. Use URLROOT . '/controller/method' for direct links, or 'javascript:void(0);' for parent items with sub-menus.
$subItems array [] An array of associative arrays, each with 'title' and 'url' keys. Creates a collapsible dropdown.
$allowedRoles array [] Array of role IDs that can see this item. Empty [] means visible to all roles.
Return Value
Returns an HTML string. If the user's role is not in $allowedRoles, returns an empty string ''.

4. Usage Examples

Example 1: Simple Link (No Sub-Menu)
A single direct link visible only to Partners (role 3). Clicking it navigates directly to the bookings page.
Code
// Simple link — visible only to Partners (role 3)
print Helper::renderMenuItem(
    'Bookings',                              // Title
    'fas fa-calendar',                       // Icon
    URLROOT . '/partner_bookings/index',     // Direct URL
    [],                                      // No sub-items
    [3]                                      // Allowed roles: Partner only
);
Generated HTML
<li>
    <a href="http://localhost/mvc-php/partner_bookings/index" class="waves-effect">
        <i class="fas fa-calendar"></i>
        <span>Bookings</span>
    </a>
</li>
Example 2: Dropdown with Sub-Items
A parent item with a collapsible dropdown containing child links. The parent $url is set to javascript:void(0); so clicking it only toggles the dropdown. Visible only to Admins (role 1).
Code
// Dropdown menu — Admin (role 1) only
print Helper::renderMenuItem(
    'Products',                     // Parent title
    'ti-package',                   // Parent icon
    'javascript:void(0);',         // No direct navigation
    [                               // Sub-items array
        ['title' => 'Add Product',    'url' => URLROOT . '/products/new'],
        ['title' => 'Products List',  'url' => URLROOT . '/products/index']
    ],
    [1]                             // Allowed roles: Admin only
);
Generated HTML
<li>
    <a href="javascript:void(0);" class="has-arrow waves-effect" aria-expanded="false">
        <i class="ti-package"></i>
        <span>Products</span>
    </a>
    <ul class="sub-menu mm-collapse" aria-expanded="false">
        <li><a href="http://localhost/mvc-php/products/new">Add Product</a></li>
        <li><a href="http://localhost/mvc-php/products/index">Products List</a></li>
    </ul>
</li>
Example 3: Multiple Roles
A menu item visible to both Admins and Managers (roles 1, 2). Simply pass multiple IDs in the $allowedRoles array.
Code
// Visible to Admin (1) AND Manager (2)
print Helper::renderMenuItem(
    'Home',
    'ti-home',
    URLROOT . '/pages/index',
    [],
    [1, 2]
);
Example 4: Visible to All Roles
To make a menu item visible to every role, list all role IDs in the array. There is no wildcard — you must include each role ID explicitly.
Code
// Support link — visible to ALL roles
print Helper::renderMenuItem(
    'Support',
    'fa fa-video',
    'javascript:void(0);',
    [
        ['title' => 'Documentation', 'url' => URLROOT . '/public/doc/index']
    ],
    [1, 2, 3, 4, 5, 6, 7, 8]   // All roles
);
Example 5: Role-Specific Home Pages
Each role sees a different "Home" link pointing to their dashboard. The menu renders only the one that matches the logged-in user's role.
Code
// Each role has its own home page:
print Helper::renderMenuItem('Home', 'ti-home', URLROOT . '/pages/index',       [], [1, 2]);  // Admin & Manager
print Helper::renderMenuItem('Home', 'ti-home', URLROOT . '/partners/index',    [], [3]);     // Partner
print Helper::renderMenuItem('Home', 'ti-home', URLROOT . '/transporter/index', [], [4]);     // Transporter
print Helper::renderMenuItem('Home', 'ti-home', URLROOT . '/drivers/index',     [], [5]);     // Driver
print Helper::renderMenuItem('Home', 'ti-home', URLROOT . '/pilots/index',      [], [6]);     // Pilot
print Helper::renderMenuItem('Home', 'ti-home', URLROOT . '/accounter/index',   [], [7]);     // Accounter
print Helper::renderMenuItem('Home', 'ti-home', URLROOT . '/greeter/index',     [], [8]);     // Greeter

// Only ONE "Home" link appears in the sidebar per user.

5. How to Add a New Menu Item

Step-by-Step Guide
Follow these steps to add a new menu entry to the sidebar:
Step 1 — Open the aside file
app/views/inc/aside.php
Step 2 — Add your renderMenuItem call
Place it inside the <?php ... ?> block, in the section for the appropriate role group.
// --- Example: Adding a "Reports" menu for Admins and Managers ---

// Simple link (no dropdown)
print Helper::renderMenuItem(
    'Reports',
    'fas fa-chart-bar',
    URLROOT . '/reports/index',
    [],
    [1, 2]
);

// OR with sub-menu dropdown
print Helper::renderMenuItem(
    'Reports',
    'fas fa-chart-bar',
    'javascript:void(0);',
    [
        ['title' => 'Daily Report',   'url' => URLROOT . '/reports/daily'],
        ['title' => 'Monthly Report', 'url' => URLROOT . '/reports/monthly'],
        ['title' => 'Export CSV',      'url' => URLROOT . '/reports/export'],
    ],
    [1, 2]
);
Step 3 — Protect the controller
Always pair menu visibility with backend access control in your controller: 
class Reports extends Controller
{
    public function __construct()
    {
        $this->session = new SessionHelper();
        // Only Admins (1) and Managers (2) can access
        $this->session->requireRoles([1, 2], 'errors/error');
    }
}
Important: Hiding a menu item does not prevent direct URL access. Always use SessionHelper::requireRoles() in the controller to enforce permissions server-side.

6. Internal Logic Flow

How renderMenuItem() Works Internally
Here is the step-by-step decision flow inside the method: 
1. Check $allowedRoles
   ├── If NOT empty → compare $_SESSION['user_role'] against the array
   │   ├── Role NOT found → return '' (item hidden)
   │   └── Role found → proceed to render
   └── If empty → proceed to render (visible to all)

2. Check $subItems
   ├── If NOT empty → add 'has-arrow' CSS class to the <a> tag
   │   └── Generate <ul class="sub-menu"> with child <li> items
   └── If empty → render as a simple direct link

3. Return the complete HTML string
